# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

CMGDB (Conley Morse Graph Database): computes Morse graphs and Conley indices of maps on rectangular phase spaces by adaptive cubical subdivision. A header-only C++ core (`include/database/` plus the CHomP-derived `include/chomp/`) is exposed to Python through pybind11 as `CMGDB._cmgdb`.

## Build and test

```bash
uv pip install '.[test]'              # or pip install '.[test]'; scikit-build-core drives CMake
uv pip install -e '.[test]'           # editable: Python edits are live, C++ edits need this rerun
python -m pytest tests -q
python -m pytest tests/test_basic.py::test_name -q
python benchmarks/benchmark.py        # correctness gate + timings; --heavy, --scenario NAME --repeat 5, --list
```

- With a non-editable install the tests import the installed copy (src layout), so reinstall after any change; with `-e` only C++ changes need a reinstall. A clean build takes about 30-60 s (one translation unit, per-tag CMake cache in `build/<wheel_tag>/`); the suite takes about 20-40 s.
- Requirements: a C++17 compiler and Boost (chrono, thread, serialization). `CMakeLists.txt` tries Boost's CMake config first and falls back to the FindBoost module (keeping CMP0167 OLD), so Boost without `BoostConfig.cmake` (EL8's 1.66) also works. sdsl-lite v3 is vendored under `src/CMGDB/_cmgdb/third_party/`; no network access is needed. GMP is optional (`USE_GMP` in `chomp/Ring.h`, off).
- `CMGDB_USE_ATLAS` is defined in `CMakeLists.txt`, and `CMGDB.cpp` has an `#error` if it is missing: upstream's `join.h` compiles the Atlas join only under it, and without it every `AtlasModel` computation throws at run time. It also compiles sdsl into the extension, hence the BSD notice in `licenses/`.
- `CMakeLists.txt` searches the headers of the pybind11 that CMake found before `/opt/homebrew/include`, which holds Homebrew's pybind11. `USER_PROJECT_PATH` (set in `pyproject.toml`'s `cmake.args`) has a default, so overriding `cmake.args` still configures.
- The `test` extra adds pybind11 so that `tests/test_build_regressions.py` can configure the project; its configure tests skip where CMake cannot find pybind11, cmake, a compiler or Boost. The other skips need torch.
- `tests/conftest.py` removes every `CMGDB_MAPGRAPH_*` variable for the session; tests that need one set it with `monkeypatch`.
- Two tests compile `tests/cpp/*.cpp` with the system `c++` against the checkout's headers, so they see header edits without a reinstall. Keep `MorseSetReachabilityCore.h` (compiled as C++11), `CarrierChainMap.h` and `GF5.h` free of Boost, SDSL and pybind11 includes. `tests/cpp/test_atlas_active_subgrid.cpp` is not run by pytest; its header gives the build command.
- `benchmarks/benchmark.py` validates each scenario against `references.json` (vertex count, unreduced edges, size and minimum box of each Morse set, Conley indices, grid size) and `references.digests.json` (a digest of each set's boxes) and exits nonzero on a mismatch. `--update-refs` rewrites them; only do that when a change is meant to alter the output.
- `tests/test_derived_graph_plot.py` renders with graphviz `dot` and fails (does not skip) without it on `PATH`.
- `CMG_VERBOSE` turns on progress and diagnostic output. Uncomment `// #define CMG_VERBOSE` at the top of `CMGDB.cpp` (above the includes) or pass `-DCMG_VERBOSE`. Without it the core is silent, including when a Conley index is left undefined.

## Architecture

### C++ core (`src/CMGDB/_cmgdb/`)

- `CMGDB.cpp` is the only translation unit. Besides the bindings it holds the `Compute*` wrappers and the native reachability queries, and several headers define non-inline globals and functions, so a second `.cpp` would fail to link.
- To expose a function: write it `inline` in a header under `include/database/`, include it in `CMGDB.cpp`, and add an `m.def` (or a `FooBinding(m)` call) in `PYBIND11_MODULE`. Pattern: copy the arguments, run the C++ work inside `py::gil_scoped_release`, build Python objects after; read anything shared, such as `has_cache()`, before releasing the GIL. Names starting with `_` are skipped by the star-import in `__init__.py`.
- `Model` holds a `Configuration` (bounds, periodic flags, `subdiv_min/max/init/limit`) and the map. The phase grid is `PointerGrid`, a `TreeGrid`. `model.phaseSpace()` returns a fresh unsubdivided grid, never the computed one. Constructors: `Model(min, max, lower, upper[, periodic], F)` with `init = 0`, `limit = 10000`; `Model(min, max, init, limit, lower, upper[, periodic], F)`; `Model(subdiv, lower, upper, F)` with `init = min = max`. `Model` does no validation: `init > min` or `max < min` silently yields an empty Morse graph (`AtlasModel` does check).
- `Compute_Morse_Graph.hpp`: subdivide `init` times, then process decomposition nodes from a priority queue. Each node builds a `MapGraph` over its grid, takes SCCs (Tarjan) and reachability, and spawns one child per Morse set (its subgrid subdivided once) until depth `max - init`. Morse-graph vertices are created at depth `min - init`; deeper levels only decide spuriousness. A node deeper than `min - init` whose grid has more than `limit` cells is neither decomposed nor refined. The results are joined in place into the grid passed in, which becomes the C++ `MorseGraph::phaseSpace()` (not bound in Python), so `MapGraph` vertex ids, `morse_set(v)` entries and `phase_space_box(i)` indices refer to one grid. `phase_space_box` does not bounds-check.
- One subdivision bisects every leaf along axis `depth % dim`. Box indices are DFS leaf order (Morton order), not row-major.
- The entry points `ComputeMorseGraph`/`ComputeConleyMorseGraph` take upstream's keyword arguments (`cache_transition_graph`, `cache_map_graph`, `batch_chunk_size`, `max_cached_edges`, `reserve_edges`, `reserve_min_edges`) through `MapGraphOptions`; their `*Only` variants, which skip the returned graph, take all but `cache_map_graph`. Both cache flags default to `None`, meaning `CMGDB_MAPGRAPH_CACHE` (default on); an explicit value wins. So the returned `map_graph` is cached by default, as the fork always did (upstream's default is lazy); upstream's `tests/test_map_graph_cache.py` asks for `cache_map_graph=False` where it needs a lazy graph. The `AtlasModel` overloads take no keyword arguments.
- Box maps: the scalar callback takes and returns a flat `[lo_0..lo_{d-1}, hi_0..hi_{d-1}]` and its length is not checked. A batch map (`Model.set_batch_map`, upstream's flat-buffer `Map::has_batch`/`batch_map` interface) receives a read-only `(count, 2*dim)` copy and must return `(count, 2*dim)` rows (list or array); other shapes raise. It is used by the cached `MapGraph`, the Conley phase (`ChompMap::images`, chunked by `batch_chunk_size`), `ComputeConleyIndexForCells` and `ComputeMorseSetReachability`; lazy graphs use the scalar map, so the two must agree. A NaN image raises `ValueError`.
- Covers clip images to the domain: escape is dropped, not modeled as a sink. Periodic axes are wrapped by at most one period, so the callback must reduce periodic coordinates. `TreeGrid::coverAccept` keeps its scratch buffers `thread_local`.
- `MapGraph.h`: CSR cache built by `build_cache` (re-entry raises), with upstream's soft `max_cached_edges` (checked per row) and the fork's environment controls: `CMGDB_MAPGRAPH_CACHE`, the `CMGDB_MAPGRAPH_RESERVE_*` hints (capped at `max_cached_edges`) and the opt-in fail-fast `CMGDB_MAPGRAPH_HARD_MAX_*` limits. The `RESERVE_*` and `HARD_MAX_*` variables are read and validated at every cache build, including the per-level caches (malformed values raise `ValueError`); `CMGDB_MAPGRAPH_CACHE` is resolved once per `Compute*` call. See the README ("Cache sizing") and `docs/map_graph_csr.md`.
- Native queries (`MorseReachabilityMasks`, `MorseSingletonReachability`, `MorseDirectedPathCells`) are exact on the cells of the cached `map_graph`: an SCC sweep of the CSR, not the Morse graph's edges, which on hierarchical runs (`init < min`) come from coarser grids and can disagree with the cell graph in both directions. `MorseReachabilityMasks` refuses Morse graphs with more than 64 nodes.
- Conley indices (`include/chomp/`) are over F_5: `Zp<5>` in `chomp/Ring.h`, the tables in `GF5.h`, `coefficient_field = 5` in results, and `ComputeCarrierChainMap` rejects other moduli. Change them together. Morse nodes store induced matrices; `annotations(v)` recomputes the shift-class strings on every call (Frobenius form in a `boost::thread`, 3600 s timeout per degree): one string per degree `0..dim`, the invariant factors with powers of `x` removed, concatenated; `"0"` means nilpotent. `[]` means undefined (or not computed).
- The Conley phase builds a cubical complex on the bounding box of the cubes of X at the depth of S (`TreeGrid::relativeComplex`, whose bounds come from the cubes it holds). A fiber chain with no preboundary returns code 2 from `RelativeMapHomology`; if S does not touch the phase-space boundary, `ConleyIndex` retries with exit images that miss the phase space projected onto it (the index of r∘F, the same as f's; see the README, "Undefined Conley indices"). Otherwise, and for non-acyclic fibers (code 1), the index is undefined.
- `ComputeConleyIndexForCells(model, morse_graph, cells, batch_chunk_size=65536)` uses X = cover(F(S)), A = X \ S and raises `ValueError` when a cell of A maps into X \ A (no index pair), and for a map-less or mismatched `Model`.
- `Zp::operator<` always returns false (a hack for `Bezout`), so never sort ring values, and `SmithNormalForm` over Z_5 can fail to terminate. CHomP calls `exit(1)` on some internal errors, which kills the Python process.
- Known defects, shared with upstream:
  - The `SmithSolve` step in `RelativeMapHomology.h` gives wrong induced maps when the coreduction Morse complex is not minimal; this reaches `ComputeConleyMorseGraph` (every `annotations(v)`), `ComputeConleyIndexForCells` and `ComputeConleyIndex`. For explicit chain complexes use `ComputeRelativeShiftClass`, which solves over the field, not `ComputeRelativeHomologyShiftClass`. Details: `~/Work/Projects/computational-hybrid/notes/2026-09-29-cmgdb-upstream-report/`.
  - On hierarchical runs with a box map that is not monotone under refinement (corner-sampled `BoxMap`), a coarse non-recurrent cell can map into a Morse set and back. `ComputeConleyMorseGraph` then annotates that set from a pair that is not an index pair (`ComputeConleyIndexForCells` refuses the same set). Example: `tests/test_conley_cells_regressions.py::test_adaptive_morse_set_that_is_not_isolated_is_refused`.
- The fork's algebra kernels `RelativeShiftClass.h`, `CarrierChainMap.h` and `GF5.h` use only the standard library; `chomp/ExplicitChainComplex.h` is the CHomP adapter behind `ComputeRelativeHomologyShiftClass`. `RelativeShiftClass.h` re-implements the shift-class string format (`FormatPolynomial`, `ShiftClassString`); keep it in sync with `chomp/PolyRing.h` and `conleyIndexString.h`, since tests compare strings.
- `AtlasModel` (`Atlas*.h`, `docs/atlas_model.md`) is a disjoint union of `PointerGrid` charts. The call order is `add_chart`, then optionally `set_active_subgrid`, then `set_map`. Vertex ids are contiguous per-chart blocks ordered by chart id over the nonempty charts. It has no Conley path (the overloads throw), and `phaseSpace()` is the initial grid; use `phase_space_chart_box` and `morse_set_chart_boxes`. A one-chart `AtlasModel` gives the same Morse graph as the `Model` with the same bounds, subdivision and map (`tests/test_atlas_join_regressions.py`).
- `ComputeMorseSetReachability` (`MorseSetReachability*.h`) re-implements `TreeGrid` geometry and cover in `ImplicitFixedTreeGrid`; mirror any change to `TreeGrid` there.

### Python layer (`src/CMGDB/`)

- `__init__.py` star-imports `_cmgdb` first and then each module. `CMGDB.MorseGraph` is therefore the DOT-parser dataclass from `morse_graph_parser`, shadowing the native class (`CMGDB._cmgdb.MorseGraph`). A new module needs an `__all__`, a line in `__init__.py`, and names that do not collide with native ones.
- Box-map builders, passed to `Model` or `AtlasModel`: `ComputeBoxMap.BoxMap` (pointwise `f`) and `BoxMapBatch`, `BoxMapData` (from sample pairs, with a spatial index; `BoxMapDataLinear` is the plain scan), upstream's `PrecomputedBoxMap` class (adaptive tree, corner or center sampling), the fork's factories `make_precomputed_box_map` / `make_adaptive_precomputed_box_map` / `make_uniform_precomputed_box_map` in `precomputed_grid.py` (wrapper class `PrecomputedLookup`), and `PrecomputedAtlasBoxMap` (exact cache keyed by `float.hex`).
- `CMGDB.PrecomputedBoxMap` is the class, and `import CMGDB.PrecomputedBoxMap as P` binds the class too, because the package attribute shadows the module. The module's tail therefore re-exports the `precomputed_grid` helpers and attaches them to the class as static methods, so `P.evaluation_offsets` and `from CMGDB.PrecomputedBoxMap import make_precomputed_box_map` keep working.
- Precomputed maps return a callable with `.batch`, which the caller installs with `model.set_batch_map(bm.batch)`. The factories take a batched `f` (`(n, d)` to `(n, d)`) or a `torch.nn.Module`; `padding` defaults to True (False in `BoxMap`); `mode="uniform"` is valid only when `init == min == max == subdiv_max`, and needs `subdiv_max` divisible by the dimension.
- Output: `PlotMorseGraph`, `PlotMorseSets` (with `PlotMorseSets1D`/`3D` and `PlotBoxesScatter`), `SaveMorseSets` (module `SaveMorseData`) and `LoadMorseSetFile`: one CSV row per box (lower bounds, upper bounds, node), with floats that round-trip exactly. The 3-D plot needs matplotlib 3.7 or later.
- Graph post-processing works on the DOT-parsed DAG: `morse_graph_parser`, `morse_lattice`, `derived_graph_plot`, `cmgdb_roa`. The bridge is to write `PlotMorseGraph(mg).source` to a file and call `MorseGraph.from_dot(path)`. Conley labels appear only for graphs from `ComputeConleyMorseGraph`; `morse_lattice` raises `ValueError` for a node whose index is undefined.
- `MapGraphCSR.py` writes and loads memory-mapped checkpoints of `map_graph.csr_view()` (`docs/map_graph_csr.md`); `MorseSetReachabilityStudy.py` repeats `ComputeMorseSetReachability` at several depths.

## Fork and releases

`origin` is `bernardorivas/CMGDB`, a fork of `marciogameiro/CMGDB` (remote `upstream`), which publishes to PyPI as `CMGDB` under the same import name. This checkout is the canonical local copy of CMGDB: projects install it with `pip install ~/Work/Software/CMGDB` or use the fork's release wheels, and do not keep their own clones. `~/Work/Projects/latent-dynamics/archive/bernardo` pins a CMGDB submodule at 7d4dfa2 ("Added UniformGrid", with its parent b460b16), which no branch here contains; its only local copy is that repo's `.git/modules/CMGDB`.

- Upstream 1.5.2 is merged (0e21503). The files where the fork deviates from upstream, and so may conflict in a future merge, are listed by `git diff --name-status --diff-filter=MD upstream/master HEAD -- . ':!src/CMGDB/_cmgdb/third_party'` (after `git fetch upstream`). Upstream's `.github/workflows/ci.yml`, `publish_wheels.yml` and `dependabot.yml` were deleted here; keep them deleted (`publish_wheels.yml` would fire on the fork's `v*` release tags).
- The version lives in `pyproject.toml`. Development versions are `X+fork.N.dev0`, where `.dev0` is part of the local label, so it sorts above `X+fork.N` and is not a pre-release; a release commit `release: X+fork.N` sets `X+fork.N` and is tagged `vX+fork.N`. The public part is the patch release after the merged upstream release (1.5.2 gives 1.5.3).
- `.github/workflows/wheels.yml` builds on a tag push and attaches the wheels to a GitHub release (no sdist). It builds cp311-cp313 wheels for manylinux_2_28 x86_64 and macOS arm64 (`[tool.cibuildwheel]` in `pyproject.toml`; Linux gets EPEL's Boost 1.78 and graphviz from `tools/cibw_before_all_linux.sh`), and runs `tools/wheel_smoke_test.py` plus the test suite. Pushes to `master` or `wheels-ci` that touch build inputs build without releasing. Push only `master` and the release tag: the local upstream tags (`v1.4.0`-`v1.5.2`) would trigger it too.
- Wheels ship the CHOMP (MIT) and sdsl-lite (BSD-3) notices from `licenses/` and leave out the C++ sources (`wheel.exclude`).
- Downstream projects pin the local version, which is what selects the fork: `pip install cmgdb==1.3.3+fork.6 --find-links https://github.com/bernardorivas/CMGDB/releases/expanded_assets/v1.3.3%2Bfork.6` (the last release, which predates the upstream merge).
